Two meanings of model metadata

Describing a model is not deploying one.

Models in the estate

Notebook 08 retains returned tables, columns, measures and relationships as observations about collected semantic models.

A model over Monitor

A separately designed semantic layer connects curated evidence, context, keys, date roles and explicit measures.

Publishing the 48 curated datasets does not automatically create a semantic model.

An inspected local model pattern

Keep curated facts and derived context separate.

Curated evidence

The 48 historical source datasets remain the analytics contract. For example, monitor_job_observations supplies Job History.

Derived model context

The local exploration model adds 20 separate monitor_report_* lookup/context Delta tables. They do not replace curated evidence.

Direct Lake model

The inspected TMDL uses Direct Lake. Source connection, framing, capacity and Desktop behavior still require environment acceptance.

This is an exploration implementation, not a mandatory hosting/storage choice or a claim of completed production acceptance.

Identity and relationships

Join through context, not repeated labels.

Workspace / Item / other entity lookups
  -> Observation Context
  -> Historical source tables, by Observation ID

Stable identities

Use observation identity for fact/context joins. Item identity includes its workspace. Names are descriptive labels, not join keys.

Distinct relationship roles

Source and related workspace/item roles remain separate. Validate unique lookup keys and filter direction.

The diagram describes model filter structure, not runtime data lineage or guaranteed change impact.

Observation grain and scope

Count the thing the measure actually describes.

Retained observations

Two statuses observed for one job are two observations, not two jobs.

Observed entities

Distinct retained workspace/item identities are not automatically a certified current inventory.

Selected evidence

Choose the appropriate source, version, mode and cycle. Do not union historical snapshots as current state.

Missing, failed or stale collection remains visible alongside business counts.

Time and permission roles

Different dates answer different questions.

Collection versus folder date

Use trustworthy observation time when present. Source Folder Date is the retained partition day, not a fabricated exact timestamp.

Event versus metric query date

Event Date describes provider events. Metric Query Date describes the capacity query period. Neither is automatically collection time.

Explicit permission mode

Choose Scoped or Tenant. The inspected model's mode filter applies to permission facts, not unrelated workspace-role observations.

Separate access evidence

Observed item grants, workspace roles and group membership do not automatically compute effective access.

Explicit measures and readiness

Do not turn every number into a total.

Named semantics

Retained observations, observed items and failed polls are different measures. Counts, durations and provider units need deliberate aggregation.

Readiness checks

The inspected model checks Unmapped Observations and lookup-build state before returning business measures.

Blank is not zero

Incomplete builds or source/context mismatch can blank measures. A readiness gate is not proof of fresh, complete API collection.

Review measure definitions and run acceptance queries in the real engine. No DAX query is executed for this deck.

Refresh order for the inspected pattern

Keep facts, context and model framing aligned.

Finish curated publication; keep competing writers idle
  -> Profile and validate the selected source versions
  -> Preview, then approve derived lookup publication
  -> Confirm lookup readiness and source consistency
  -> Refresh/reframe the semantic model; verify measures
The derived lookup build is not a cross-table transaction and is not Notebook 06's rerun experiment.

Accept access and deployment separately

Test privately before sharing a model.

Source and audience access

Verify model identity, OneLake permissions, capacity, licensing and any required RLS/OLS or export policy. Hidden fields are not an authorization boundary.

Private acceptance target

Use an approved isolated model for testing. Do not attach to or overwrite a shared model by assumption. Remote modeling can persist changes immediately.

Local artifact inspection does not prove Desktop source evaluation, DAX correctness, access isolation or production performance.

The collection-to-model foundation

One evidence journey. Explicit boundaries.

Explore and collect

Start on Windows, Linux or optional WSL2. Choose approved modules and protect retained evidence.

Host and curate

Choose Function App or notebook hosting. Validate the Lakehouse handoff, preview, publish serially and test reruns.

Model with context

Preserve observation grain, dates, coverage and scope. Verify relationships, measures, access and refresh behavior.
