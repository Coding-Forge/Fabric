Fabric Monitor / Episode 02

Explore locally.
Keep the scope deliberate.

A proof of concept on Windows, Linux or optional WSL2.

Prepare the environment, choose approved modules and understand the retained evidence.

Before the first run

Local is a destination, not an offline mode.

Prepare the tools

Python 3.12, Git and a repository checkout. Run commands from the repository root.

Approve access

Real API credentials, required tenant settings and endpoint-specific permissions.

Protect the output

A restricted local folder outside source control. Required monitored capacities available.

No Function App, storage account or Fabric notebook is required for standalone local collection.

Native Windows / PowerShell

Create an isolated Python environment.

Set up from the repository root

python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt

Without script activation

.\.venv\Scripts\python.exe -m pip install -r requirements.txt

Use that interpreter for later Python commands if activation is unavailable.

Native Windows does not require Linux or WSL. Follow your organization's execution policy.

Linux / optional WSL2

The same collector, a different shell.

Set up from the repository root

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt

WSL2: best of both worlds

Keep Windows applications and use a Linux development environment. Maintain a separate Linux checkout and virtual environment.

Choose the environment you prefer. API scope and authorization rules do not change.

Choose the output destination

Make the local destination explicit.

Windows PowerShell

$env:LOCAL_OUTPUT_PATH =
  "$HOME\monitor-poc-output"

Linux / WSL2

export LOCAL_OUTPUT_PATH="$HOME/monitor-poc-output"
LOCAL_OUTPUT_PATH takes precedence over Blob and Lakehouse destinations. The application creates the folder if needed.

Configure privately

Credentials stay out of the recording.

Required API identity

TENANT_ID
CLIENT_ID
CLIENT_SECRET

Select the intended CLOUD_ENVIRONMENT. Commercial is the default.

Scope is a separate choice

Admin API authorization is not universal resource access. Non-Admin features and Graph have their own permissions and collection boundaries.

Use an approved private configuration source. Never display secret values, credential profiles or authentication output.

Approve, then collect

Select modules explicitly.

python -m app.monitor --modules Activity,Catalog

Illustrative selection

Activity and Catalog are examples, not a universally approved or workspace-limited scope.

Before execution

Confirm permissions, API boundaries, output destination and collection approval.

This starts a real collector invocation. We are showing the command, not executing it.

Inspect and retain

Keep the evidence and its context.

Illustrative layout

monitor-poc-output/
  state.yaml
  activity/
    YYYY/MM/DD/
      ...

Check the outcome

Review module results, applicable coverage and freshness. A completed invocation does not establish a complete current tenant inventory.

Preserve state, progress controls and cooldowns. Do not delete them to force retries.

An alternative local host

Standalone Python is not the Functions host.

Standalone Python

Invoke the application directly. No Azurite or Functions runtime is needed for local-folder output.

Local Functions host

Requires Core Tools and runtime storage. Core Tools loads local.settings.json. Collection runs on host startup.

DRY_RUN is not an offline switch. Do not start a host or collector just to preview configuration.
